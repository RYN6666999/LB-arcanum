# good-questions.md — 對齊四問的好問題庫

> 用途:align-before-build skill 提問時的參考。
> 原則:問到能逼出「具體 + 沒意識到」的答案,才算好問題。

---

## 第 0 問 · Why(為什麼做)
**要逼出的假設:** 真正的目的,而非表面需求。

| 爛問法 | 好問法 |
|---|---|
| 「你想做什麼?」 | 「做完這件事,你會怎麼用它?給誰用?」 |
| 「目的是什麼?」 | 「三個月後,你怎麼判斷這件事做對了?」 |
| 「為什麼要做這個?」 | 「如果這個不存在,你現在怎麼應付?那個應付方式哪裡卡?」 |
| 「有什麼背景嗎?」 | 「是有什麼事讓你今天想做這件事,還是想了很久?」 |

**追問技巧:當對方答不出 Why 時,怎麼引導?**
換問「這件事做完之後,你要拿去做什麼?」——聚焦下游行為,比問動機更容易答。
或者往反面問:「如果我做出來你不滿意,最可能是哪裡不對?」，Why 往往藏在那個「不對」裡。

## 第 1 問 · What(具體例子)
**要逼出的假設:** 抽象描述底下藏的真實期待。

| 爛問法 | 好問法 |
|---|---|
| 「你想要什麼?」 | 「給我一個真實的例子:輸入是什麼、你期待看到的輸出是什麼?」 |
| 「大概是什麼樣子?」 | 「下週你把這個拿給對方看,你希望對方說出哪一句話?」 |
| 「功能需求有哪些?」 | 「你現在最想先解決的那一個場景,從頭說一遍:誰做了什麼、卡在哪、你要的結果是什麼?」 |
| 「範圍是什麼?」 | 「有沒有一個你已經做過、但不夠好的版本?那個哪裡不夠?」 |

**追問技巧:對方只給抽象描述時,怎麼逼出具體例子?**
說:「這個我聽懂了方向,但我需要一個真實情境——上次你碰到這個問題時,當時的輸入是什麼?你期待的輸出是什麼?」
若對方說「還沒有真實案例」,改問:「你腦子裡最典型的那個使用者,他會怎麼用這個東西?演一遍給我聽。」

## 第 2 問 · How(味道 / 靈魂)★重點,範例最多
**要逼出的假設:** 跑掉就「不對味」的精神、識別、風格。

| 爛問法 | 好問法 |
|---|---|
| 「你想要什麼風格?」 | 「你最挑剔的那個用戶,看完之後最可能嫌哪一點?」 |
| 「有沒有參考?」 | 「有沒有一個東西——不一定同領域——你看了會說『對,就這味』?說說它哪裡對。」 |
| 「品質要求是什麼?」 | 「有沒有一個你看了會說『千萬不能變成這樣』的反例?它哪裡讓你不舒服?」 |
| 「語氣要怎樣?」 | 「如果這東西會說話,它是哪種人?嚴肅還是隨和?直接還是迂迴?舉個你認識的人當例子。」 |
| 「有什麼特別要求嗎?」 | 「三個月後你回來看這個,你最希望它還保留著的那一個特質是什麼?」 |
| 「要有個性嗎?」 | 「這個東西做給誰看?那個人最在意什麼?他看到什麼會立刻關掉?」 |

**追問技巧:風格說不清楚時,怎麼用對比/範本逼出來?**

1. **對比法**:「A 和 B 你比較喜歡哪個?說說為什麼。」——不需要對方能描述風格,只要能選邊站。
2. **反例法**:「最近有沒有看到什麼東西讓你覺得很糟糕?它哪裡爛?」——人對「不對味」的感知往往比「對味」更清晰。
3. **擬人法**:「如果這個產品/文章/功能是一個人,他走進房間你希望大家對他的第一印象是什麼?」
4. **範本錨定**:「你心目中這個領域做得最好的三個例子是什麼?」然後追:「它們共同有、你不想丟掉的是哪一點?」

## 第 3 問 · 邊界(紅線 / 何時停)★重點,範例最多
**要逼出的假設:** 默認不會發生、其實會發生的危險。

| 爛問法 | 好問法 |
|---|---|
| 「有什麼限制嗎?」 | 「什麼情況下你寧可我停下來問你,也不要我自己判斷往前走?」 |
| 「有什麼不能做的?」 | 「如果我做完了你卻說『這個要全部重來』,最可能是因為我碰了什麼?」 |
| 「預算是多少?」 | 「這件事花超過多少時間/錢,你就會覺得不值得,寧可換個做法?」 |
| 「有什麼敏感的地方嗎?」 | 「這裡面有沒有碰了會出大事的東西——不管是技術上、人際上、還是法律上?」 |
| 「截止日是什麼時候?」 | 「這個要在什麼時間點之前拿到才有用?晚一天有差嗎?晚一週呢?」 |
| 「有什麼要特別注意的?」 | 「有沒有我很可能默認成立、但其實你完全不接受的東西?」 |

**補充:不可逆操作的紅線問法**
「這件事裡面有沒有做了就很難回頭的步驟?你希望在那一步之前我一定要先讓你確認?」

## 複述階段 · 點破矛盾(直接版)
**要做的:** 看到需求打架或缺口,直接講 + 帶判斷 + 等拍板。

**常見矛盾型態與點破範例:**

**「又要快又要精細」型**
> 「你說兩天內要有初版,又說每個細節都要品質過關。這兩個我同時做到的機率很低。我的判斷是先交一個功能完整但細節粗糙的版本,你確認方向對了再精修。你怎麼看?」

**「沒提到 ___ 但一定會踩」型**
> 「你沒提到手機版的體驗,但這個東西大部分人會用手機開。如果我只做桌面版,上線後可能會有問題。你要我現在一起做,還是先標記起來之後處理?」

**「反覆強調 ___,其實這是核心」型(照鏡子)**
> 「你說了三次『一定要讓用戶覺得快』。我的感覺是速度不只是加分項,而是這個產品的核心。是這樣嗎?如果是,我會把它當架構決策,不只是最後優化。」

**「目標對象說不清楚」型**
> 「你說目標用戶是『一般人』,但你剛才描述的使用場景聽起來是已經有點基礎的人。這兩個的設計方向差很多。你要我先鎖定哪一種?」

**「功能清單很長,但沒說什麼最重要」型**
> 「你列了十二個功能。如果只能先上三個,你會選哪三個?——不是說砍掉其他的,是幫我知道什麼是核心、什麼是加分。」

## 跨領域速查
同一問,不同任務怎麼換問法:

| | 寫程式 | 做課程 | 寫文案 | 做設計 |
|---|---|---|---|---|
| **味道是什麼** | 「這個 codebase 三年後還在維護,最重要的一個特質是什麼?可讀性?效能?可擴展?」 | 「學完這堂課,你希望學員說的那一句話是什麼?」 | 「這篇文章讀完,你希望讀者腦子裡留下的那一個念頭是什麼?」 | 「這個設計放到競品旁邊,你希望用戶一眼看到什麼不一樣?」 |
| **紅線通常是** | 「哪些第三方套件/服務不能碰?哪些既有架構不能動?」 | 「有沒有你絕對不想在課程裡說的立場或觀點?」 | 「有沒有品牌不能碰的詞、不能做的比較、法律上的限制?」 | 「有哪些既有的視覺識別或元件是一定要沿用的,不能改的?」 |
